uKey Architecture
Kernel Driver & Cryptographic Chain

How It Works: Under The Hood

uKey bypasses complex, brittle user-space hacks by speaking directly to the Linux Kernel via user-space HID emulation (/dev/uhid), making the phone appear as a certified USB security dongle.

Layer 01 • Linux Kernel

🐧 User-Space HID Emulation

The Linux daemon opens /dev/uhid and registers a USB HID device with the standard FIDO2 usage page (0xF1D0). To Google Chrome, Firefox, OpenSSH, and PAM, your system sees a genuine physical USB token plugged into a motherboard port.

HID Report Descriptor: 0xF1D0 (FIDO Alliance)
Packet Framing: 64-byte CTAPHID (Init & Cont)
Layer 02 • Android Hardware

🔒 StrongBox KeyStore Silicon

Cryptographic keypairs are generated inside the phone's dedicated hardware security module (StrongBox or ARM TrustZone TEE). The private key never enters device RAM and cannot be extracted even by a root user or kernel debugger.

Key Type: ECDSA NIST P-256 (COSE -7)
Hardware Guard: KeyProperties.PURPOSE_SIGN
The 3-Step Cryptographic Handshake
1

Challenge Generation (Linux Host)

When you trigger sudo or a WebAuthn portal, pam_u2f or the browser generates a 32-byte cryptographic challenge (SHA-256 clientDataHash) and sends it across the virtual USB pipe via CTAP2 authenticatorGetAssertion.

2

Out-of-Band Mobile Prompt (Android Phone)

The phone receives the challenge over the local socket. The Android OS displays native BiometricPrompt showing the exact requesting application. Biometrics are verified in hardware; no fingerprint data leaves silicon.

3

Hardware Signature & Instant Unlock (<400ms)

The StrongBox chip calculates an ECDSA signature over authenticatorData || clientDataHash with User Present (UP=1) and User Verified (UV=1) flags. The assertion returns through /dev/uhid, and Linux grants access.

Privacy & Zero-Trust Guarantees
• Zero Biometrics Transferred: Fingerprint minutiae templates remain permanently locked inside the phone's chip. Only ephemeral digital signatures cross the wire.
• Zero Third-Party Relays: Works 100% offline via local USB cable or loopback Wi-Fi. No Google, AWS, or cloud relays.
• Unphishable: FIDO2 mathematically binds credentials to the domain origin. Malicious phishing links cannot clone assertions.
