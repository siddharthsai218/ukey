UNIFIED ARCHITECTURE

Laptop-First, Phone-Fallback.

What if your laptop already has a built-in fingerprint sensor? uKey implements an adaptive hardware cascade: use your laptop's local sensor when available, and fall back to your phone's StrongBox when it's not.

TIER 01 • LAPTOP BUILT-IN SENSOR

Local fprintd Sensor

If your ThinkPad or Framework laptop has a working fingerprint reader, Linux PAM invokes pam_fprintd.so first. Authenticate sudo in 0.4s without reaching for your phone.

# PAM Priority 1
auth sufficient pam_fprintd.so
TIER 02 • UKEY PHONE ENCLAVE

Phone StrongBox Bridge

No laptop sensor? Laptop closed in a desktop dock? Or performing FIDO2 WebAuthn / OpenSSH signing that libfprint cannot do? uKey prompts your phone's biometric hardware enclave via /dev/uhid.

# PAM Priority 2 & WebAuthn / SSH
auth sufficient pam_u2f.so ...
TIER 03 • SYSTEM FALLBACK

0.0s Password Auth

Phone battery depleted, device untethered, or sensor soiled? Linux drops cleanly to standard UNIX password authentication in 0.0s. Zero lockouts.

# PAM Priority 3
auth required pam_unix.so try_first_pass

Not a cloud passkey.

Not a browser extension.

A native hardware security key.

Google and Apple passkeys route through Bluetooth, require cloud rendezvous, and only work inside browser tabs. They cannot unlock your Linux terminal. They cannot authenticate sudo. They cannot sign an OpenSSH commit.

uKey bypasses all of that. By emulating a real USB Human Interface Device directly inside the Linux kernel on /dev/uhid, your desktop sees an actual plugged-in YubiKey—powered by the tamper-resistant hardware enclave already inside your pocket.

< 5 ms

Hardware cryptographic signing time inside Android's StrongBox Keymaster. From kernel event to authenticated return with zero cloud transit.

LAYER 01
Kernel /dev/uhid
Emulates a physical USB HID token over BUS_USB with the FIDO usage page 0xF1D0 (Vendor 0x1209, Product 0x0001).
LAYER 02
CTAPHID Framing
Handles 64-byte segmented packets, channel allocation (CID), and 100ms keep-alive pulses.
LAYER 03
CTAP2 State Machine
Strict CBOR encoding for authenticatorMakeCredential and authenticatorGetAssertion (ES256).
LAYER 04
Local TCP Bridge
Length-prefixed JSON wire protocol over USB (adb reverse) or local Wi-Fi. Zero external telemetry.
LAYER 05
Android StrongBox / TEE
Hardware-isolated NIST P-256 keys (AUTH_BIOMETRIC_STRONG) in the StrongBox enclave. Gated by BiometricPrompt; keys never leave silicon.

The tough questions, answered.

How is this different from mahirsn/passkey on Google Play? ▾
mahirsn/passkey uses Bluetooth (BLE) and USB. On Linux, Bluetooth LE has 1,500ms to 3,000ms latency, frequent BlueZ pairing drops, and many desktop PCs lack BLE hardware entirely. Furthermore, it lacks native Linux PAM integration and desktop auto-lock.

uKey uses zero-trust Wi-Fi LAN + USB with <5ms latency, single-use PIN pairing, native pam_u2f for instant terminal sudo, ecdsa-sk for git push, and systemd session auto-lock.
Can this replace the username and password when I git push? ▾
Yes! OpenSSH 8.2+ natively supports FIDO2 security keys via the ecdsa-sk key type. Run ssh-keygen -t ecdsa-sk -f ~/.ssh/id_ukey, touch your phone's sensor to generate the key, and add ~/.ssh/id_ukey.pub to your GitHub account under SSH Keys. Every git push will verify your fingerprint on your phone!
Can strangers on the same Wi-Fi intercept my keys or logins? ▾
No. First, your private key NEVER leaves your phone's Android StrongBox silicon. Second, Wi-Fi connections require a one-time 6-digit PIN pairing that yields a 256-bit device token. All handshake frames use HMAC-SHA256 challenge-response with random nonces. Unpaired or rogue Wi-Fi connections are dropped by the daemon in <4ms.
What happens if my phone dies or is in another room? Am I locked out? ▾
No, never. The PAM rule uses auth sufficient pam_u2f.so. If your phone is unreachable, or if you press Enter, Linux immediately falls back to your regular Linux password in 0.0s with zero hangs. You can also disable uKey anytime with ukeyctl off.
Does biometric data get sent over the network? ▾
No. This is zero-knowledge local signing. Your fingerprint never leaves the phone — it's consumed inside the Android biometric + Keystore stack to authorize a signature. What crosses the (loopback) link is only the public key and the resulting ECDSA signature. The private key is non-exportable and never leaves the StrongBox silicon.
