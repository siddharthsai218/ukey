SILICON-LEVEL ISOLATION

Why software authenticator apps fail.

Bluetooth passkey apps on Google Play run inside userland OS storage. uKey binds every private key directly into dedicated tamper-resistant hardware silicon.

VULNERABILITY 01

Bluetooth HID Spoofing

Apps like sn.mahir.passkey emulate generic Bluetooth keyboards over RF. They broadcast keystrokes across the 2.4GHz spectrum without channel binding, making them susceptible to nearby RF sniffing and keystroke spoofing. Furthermore, Bluetooth keyboards cannot provide hardware FIDO2 user presence to Linux PAM.

VULNERABILITY 02

Userland Key Extraction

Standard apps store passkeys in Android SQLite or shared preferences files. A compromised phone or rooted device can dump the database in milliseconds. In contrast, uKey keys are generated inside Google Titan M or Samsung Knox StrongBox (EAL5+ certified). Private keys never touch RAM, never touch flash, and cannot be exported even by root.

THE UKEY STANDARD

Kernel /dev/uhid Integration

uKey creates an authentic virtual FIDO2 / CTAP2 hardware key directly in the Linux kernel via /dev/uhid. To the Linux operating system, OpenSSH, Chrome, and Firefox, your phone appears identically to a $60 USB YubiKey 5 plugged into the motherboard.

FREQUENTLY ASKED QUESTIONS

Everything you need to know.

What happens if my phone battery dies? Will I be locked out of sudo?
No, you will never be locked out. uKey’s PAM module is configured as sufficient. If your phone is unplugged, powered off, or disconnected, uKey immediately yields to the Linux password prompt in 0.0 seconds. You simply press Enter or type your password as usual.
How is this different from Bluetooth passkey apps on the Play Store?
Apps like sn.mahir.passkey emulate generic Bluetooth keyboards over the air. They do not emulate kernel FIDO2 security keys, cannot do Linux PAM sudo elevation, cannot sign OpenSSH keys, and store credentials in software userland. uKey binds keys into Android StrongBox hardware silicon and creates an authentic kernel /dev/uhid device on Linux.
Is local Wi-Fi pairing safe on public coffee shop networks?
Yes. When using Wi-Fi, every packet must include an authentic HMAC token hash generated using a paired 6-digit cryptographic PIN. If an unauthorized attacker or rogue scanner on the LAN attempts to hit port 8443, the daemon drops the connection in under 4ms with zero processing.
