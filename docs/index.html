DEFENSE-IN-DEPTH • ZERO TRUST

Engineered for Untrusted Wi-Fi Networks.

Unlike Bluetooth which transmits in the clear, uKey uses a one-time 6-digit PIN pairing architecture. Strangers on the same Wi-Fi cannot see your keys or forge authentications.

1. One-Time 6-Digit PIN

Pair your phone once using a cryptographically generated 6-digit PIN. The daemon issues a unique 256-bit device token stored in Android's secure preferences. No passwords to remember.

ukeyctl pair • 15min expiry
2. HMAC-SHA256 Challenge-Response

The daemon drops unauthenticated TCP packets in <5ms. Bearer tokens are never sent in the clear; replay attacks are mathematically prevented via single-use nonces.

Sub-5ms Rogue Drop
3. 0.0s Password Fallback

Phone in another room or out of battery? Linux PAM sufficient fallback immediately prompts for your normal UNIX password with zero delay. You are never locked out.

Zero Hangs • Instant Fallback
4. Automatic Desktop Lock

Walk away from your desk with your phone? The daemon monitors the bridge socket. When disconnected, it calls loginctl lock-session to lock your screen automatically.

FREQUENTLY ASKED QUESTIONS

The Tough Questions, Answered.

How is this different from mahirsn/passkey on Google Play? ▾
mahirsn/passkey uses Bluetooth (BLE) and USB. On Linux, Bluetooth LE has 1,500ms to 3,000ms latency, frequent BlueZ pairing drops, and many desktop PCs lack BLE hardware entirely. Furthermore, it lacks native Linux PAM integration and desktop auto-lock.

uKey uses zero-trust Wi-Fi LAN + USB with <5ms latency, single-use PIN pairing, native pam_u2f for instant terminal sudo, ecdsa-sk for git push, and systemd session auto-lock.
Can this replace the username and password when I git push? ▾
Yes! OpenSSH 8.2+ natively supports FIDO2 security keys via the ecdsa-sk key type. Run ssh-keygen -t ecdsa-sk -f ~/.ssh/id_ukey, touch your phone's sensor to generate the key, and add ~/.ssh/id_ukey.pub to your GitHub account under SSH Keys. Every git push will verify your fingerprint on your phone!
Can strangers on the same Wi-Fi intercept my keys or logins? ▾
No. First, your private key NEVER leaves your phone's Android StrongBox silicon. Second, Wi-Fi connections require a one-time 6-digit PIN pairing that yields a 256-bit device token. All handshake frames use HMAC-SHA256 challenge-response with random nonces. Unpaired or rogue Wi-Fi connections are dropped by the daemon in <5ms.
What happens if my phone dies or is in another room? Am I locked out? ▾
No, never. The PAM rule uses auth sufficient pam_u2f.so. If your phone is unreachable, or if you press Enter, Linux immediately falls back to your regular Linux password in 0.0s with zero hangs. You can also disable uKey anytime with ukeyctl off.
Does biometric data (fingerprint scans) leave my phone? ▾
Never. Biometric matching happens entirely inside Android's BiometricPrompt and StrongBox hardware. The daemon and laptop only receive the signed ECDSA assertion data. No raw biometric imagery or templates ever cross the wire.
