The world's first virtual FIDO2 key for Linux.

Your Android phone becomes a real USB security key. Not a browser extension: the Linux kernel sees a physical token on /dev/uhid, and your phone's hardware enclave signs for sudo, git push, and WebAuthn.

Google and Apple passkeys only work inside browser tabs. They cannot unlock your Linux terminal. They cannot authenticate sudo. They cannot sign an OpenSSH commit.

uKey emulates a physical USB HID device directly in the Linux kernel. Any application or website that supports physical YubiKeys works natively out of the box.

01 / KERNEL

/dev/uhid

Emulates a physical USB HID security token over BUS_USB with FIDO usage page 0xF1D0.

02 / PROTOCOL

CTAPHID

64-byte segmented packets, channel allocation (CID), and 100ms keep-alive pulses.

03 / ENGINE

CTAP2 CBOR

Strict CBOR encoding for authenticatorMakeCredential and authenticatorGetAssertion.

04 / TRANSPORT

Local Bridge

Zero-telemetry TCP bridge over USB loopback (adb reverse) or paired Wi-Fi LAN.

05 / SILICON

Android StrongBox

Hardware-isolated NIST P-256 keys (CC EAL5+). Keys never leave silicon even with root.

Engineered for untrusted networks.

Unlike Bluetooth which transmits in the clear, uKey uses a defense-in-depth zero-trust pairing architecture.

01 / PAIRING

One-Time 6-Digit PIN

Pair your phone once using a cryptographically generated 6-digit PIN. The daemon issues a unique 256-bit device token stored in Android's secure preferences. No passwords to remember.

02 / HANDSHAKE

HMAC-SHA256 Challenge

The daemon drops unauthenticated TCP packets in <4ms. Bearer tokens are never sent in the clear; replay attacks are mathematically prevented via single-use nonces.

03 / SILICON

Android StrongBox Enclave

Private keys are generated directly inside tamper-resistant hardware silicon (CC EAL5+). Biometric matching occurs inside Android Keystore; raw fingerprint images never leave the device.

One command. Any distribution.

  1. Install the daemon

    Installs /dev/uhid kernel rules, systemd user service, and validation tools.

    $ curl -fsSL https://raw.githubusercontent.com/siddharthsai218/ukey/main/install.sh | bash

  2. Configure sudo

    Sets up pam_u2f with 0.0s password fallback. If your phone is away, Linux prompts for your normal password immediately.

    $ sudo ./scripts/setup_pam_sudo.sh

  3. OpenSSH Git Push

    Generate a hardware-backed FIDO2 SSH key. Replace GitHub personal access tokens with phone fingerprint verification.

    $ ssh-keygen -t ecdsa-sk -f ~/.ssh/id_ukey

The tough questions, answered.

How is this different from mahirsn/passkey on Google Play? ▾

mahirsn/passkey uses Bluetooth (BLE) and USB. On Linux, Bluetooth LE has 1,500ms to 3,000ms latency, frequent BlueZ pairing drops, and many desktop PCs lack BLE hardware entirely. Furthermore, it lacks native Linux PAM integration and desktop auto-lock.

uKey uses zero-trust Wi-Fi LAN + USB with <5ms latency, single-use PIN pairing, native pam_u2f for instant terminal sudo, ecdsa-sk for git push, and systemd session auto-lock.

Can this replace the username and password when I git push? ▾

Yes. OpenSSH natively supports FIDO2 security keys via the ecdsa-sk key type. Run ssh-keygen -t ecdsa-sk -f ~/.ssh/id_ukey, touch your phone's sensor to generate the key, and add ~/.ssh/id_ukey.pub to your GitHub account under SSH Keys. Every git push will verify your fingerprint on your phone.

Can strangers on the same Wi-Fi intercept my keys or logins? ▾

No. First, your private key NEVER leaves your phone's Android StrongBox silicon. Second, Wi-Fi connections require a one-time 6-digit PIN pairing that yields a 256-bit device token. All handshake frames use HMAC-SHA256 challenge-response with random nonces. Unpaired or rogue Wi-Fi connections are dropped by the daemon in <4ms.

What happens if my phone dies or is in another room? Am I locked out? ▾

No, never. The PAM rule uses auth sufficient pam_u2f.so. If your phone is unreachable, or if you press Enter, Linux immediately falls back to your regular Linux password in 0.0s with zero hangs. You can also disable uKey anytime with ukeyctl off.

Does biometric data (fingerprint scans) leave my phone? ▾

Never. Biometric matching happens entirely inside Android's BiometricPrompt and StrongBox hardware. The daemon and laptop only receive the signed ECDSA assertion data. No raw biometric imagery or templates ever cross the wire.
